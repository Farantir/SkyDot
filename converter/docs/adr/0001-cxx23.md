# ADR 0001 — C++23, not C++20

**Status:** accepted
**Date:** 2026-08-22

## Context

The research notes chose C++20, but the `SpanReader` API was designed around
`std::expected`, which is C++23. Error handling depends on returning `expected`
instead of throwing, so the API wins.

## Decision

Build with `-std=c++23`. Use `std::expected` and nothing else from C++23: no
deducing-this, `std::print`, `std::mdspan` or post-C++20 ranges.

## Consequences

- Minimum compilers: GCC 14, Clang 18, MSVC 19.38. CI already uses newer ones.
- If a target lacks `std::expected`, `bethconv::io::ParseResult<T>` is a single
  alias and can be pointed at a hand-written `expected`.
- `std::expected<void, E>` is used for operations that can only fail (`seek`,
  `skip`); a fallback would need to cover that case.
